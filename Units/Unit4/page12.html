Section 12: Wave Manager Basics

Create a wave system with data-driven wave definitions.

What is an autoload?

An autoload is a script Godot loads once when the game starts and keeps alive for the whole run. Every other script can reach it by name, no matter what scene is currently open. That makes it the right home for information the whole game needs: which wave you are on, how much fence durability is left, and later, how much gold you have.

You have used this pattern before. Unit 1 kept level information in a Global autoload, and Unit 3 kept hunger and health in one. This section uses the same pattern for a new job. Instead of each scene holding its own copy of a number, the number lives in one place every script already knows: Global.

What is a resource?

A resource is data saved as a file. Instead of writing wave numbers inside a script, you describe a wave in a file: which enemies, how many of each, how far apart. The script reads the file and runs whatever it describes. Change the file, and the wave changes, with no code touched. A resource can hold other resources. A wave holds a list of entries, and each entry is a small resource of its own: one enemy scene, its count, and whether it is a boss.

So far, numbers have lived in @export variables on scenes. That works for one tower or one enemy, because each scene holds its own values. A wave is not one thing, it is a list of things, and lists belong in data, not in code. Resources let you build a whole set of waves as files in a folder, then hand the script the set and let it work through them.

One Script To Bind Them

  • Waves need numbers that exist outside any one scene: which wave is next, and how much fence is left. That is what an autoload is for.
  • Create a script and save it as scripts/global.gd:

extends Node

var current_wave = 0
var fence_durability = 20
  • Open Project Settings, go to the Autoload tab, and add global.gd with the name "Global".
  • An autoload is a single instance that exists from game start. Any script can read and change it as Global, with no reference to pass around.
  • Mine is 20 for fence_durability for now, but yours can be anything. Your GDD decides how much fence your base has.

A Wave You Can Edit in the Inspector

  • A wave definition is data in the inspector, so we don't need to change the spawner code each time.
  • A wave holds more than one enemy type. Each type gets an entry: one scene and how many of it. The wave is the list of entries.
  • Create a script and save it as scripts/wave_entry.gd:

extends Resource
class_name WaveEntry

@export var enemy_scene: PackedScene
@export var enemy_count = 5
@export var is_boss = false
  • Each entry will be a resource that we create.
  • is_boss is off by default, so ordinary entries are unchanged.
  • A boss wave is a special wave, and your GDD decides how often boss waves appear.
  • Create a script and save it as scripts/wave_def.gd:

extends Resource
class_name WaveDef

@export var entries: Array[WaveEntry]
@export var spawn_interval = 1.0
  • Now make your first wave. In the FileSystem dock, right click on the resource folder, create a new Resource, pick WaveDef, and save it as waves/wave_1.tres. In the Inspector, set the entries array size, pick New WaveEntry for each element, and set each enemy scene and count.
  • Entries are inside the wave file. They are sub-resources, so a wave needs no separate files for its entries.
  • You already have two enemy types from Section 4, so your first wave can mix them. Mine is 5 of my first enemy and 3 of my second, 1 second apart, but yours can be anything. Your GDD decides what your first wave looks like.
💡 GDD Check: Check your GDD. What is your first wave made of? Which enemy types, and how many of each? Use those values in wave_1.tres.

Spawning One Wave

  • Add a Node child to your main scene and name it "WaveManager"
  • Add a Timer child to WaveManager and name it "SpawnTimer". Turn on One Shot.
  • Attach a script and save it as scripts/wave_manager.gd
  • Start the script with exports and state:

extends Node

@export var path: Path3D
@export var waves: Array[WaveDef]

@onready var spawn_timer = $SpawnTimer

var wave_active = false
var current_wave_def: WaveDef
var spawn_queue: Array[PackedScene] = []
var spawning_done = false
  • Drag your Path node into the path slot in the Inspector
  • In the Inspector, set the waves array size and drag wave_1.tres into a slot
  • Add the input action for starting a wave. Open Project Settings, go to Input Map, add an action called "start_wave", and give it a key. Mine is Space.
  • Add starting and spawning to scripts/wave_manager.gd:

func _unhandled_input(event):
	if event.is_action_pressed("start_wave") and not wave_active:
		start_wave()

func start_wave():
	if Global.current_wave >= waves.size():
		print("No more waves")
		return
	current_wave_def = waves[Global.current_wave]
	spawn_queue.clear()
	for entry in current_wave_def.entries:
		if entry.is_boss:
			print("Boss wave!")
		for i in entry.enemy_count:
			spawn_queue.append(entry.enemy_scene)
	if spawn_queue.is_empty():
		print("Wave is empty")
		return
	spawning_done = false
	wave_active = true
	spawn_timer.wait_time = current_wave_def.spawn_interval
	spawn_enemy()

func spawn_enemy():
	var follow = PathFollow3D.new()
	follow.loop = false
	path.add_child(follow)
	var enemy = spawn_queue.pop_front().instantiate()
	follow.add_child(enemy)
	if spawn_queue.is_empty():
		spawning_done = true
	else:
		spawn_timer.start()
  • Connect the SpawnTimer timeout signal to _on_spawn_timer_timeout, and add the handler:
func _on_spawn_timer_timeout():
	spawn_enemy()
  • start_wave flattens the entries into a queue: each entry's scene, repeated its count, in array order. spawn_enemy pops the front of the queue each time it runs.
  • Entries spawn in array order. The whole first entry spawns before the second begins, so the array order is the wave's script.
  • for i in entry.enemy_count counts that many times. i is never used, it only counts.
  • An empty queue means an empty wave, so start_wave stops before the wave goes active.
  • The queue is rebuilt every wave, so a wave always spawns exactly what its entries describe.
  • The first enemy spawns at once, so the key press feels responsive. The rest follow on the timer.
  • The boss print fires while the queue builds, so it appears before the first enemy spawns, and one print per boss entry means a wave with two bosses prints twice.
  • The flag also lets later sections find boss entries, and Section 13 uses it to add extra bosses each cycle.
  • follow.loop = false is because a follow created in code defaults to looping, so without this line your enemies would wrap back to the start instead of reaching the Base.
  • Waves start on a key press, not on a timer. The player decides when the next wave begins.

Knowing When a Wave Is Over

  • A wave is over when every spawned enemy is gone and none are left walking. Add the check to scripts/wave_manager.gd:

func _process(delta):
	if wave_active and spawning_done and get_tree().get_nodes_in_group("enemies").is_empty():
		wave_active = false
		Global.current_wave += 1
		print("Wave complete")
  • The enemies group from Section 4 does this job. When it is empty, nothing is left alive.
  • wave_active guards the check, so it cannot fire before the first wave starts.
  • Reaching the Base no longer despawns the enemy. It stops there and attacks the fence until a tower kills it or the fence falls. Add an attack interval and a timer to scripts/enemy.gd:

@export var attack_interval = 1.0

var attack_timer = 0.0
  • Replace the movement and path-end part of _process with this. The old follow.queue_free() at the path end goes away:

func _process(delta):
	if follow.progress_ratio >= 1.0:
		attack_timer += delta
		if attack_timer >= attack_interval:
			attack_timer = 0.0
			if Global.fence_durability > 0:
				Global.fence_durability -= damage
				if Global.fence_durability <= 0:
					print("Game Over")
	else:
		follow.progress += move_speed * delta
  • The enemy stops moving once it reaches the Base, because progress only increases in the else.
  • The fence guard stops the number going negative and stops repeat game-over prints once the fence has fallen.
  • Mine is 1 second between hits, but yours can be anything. Your GDD decides how fast your enemies chew the fence.
  • damage comes from Section 4. If your enemy.gd is missing it, add the export.
  • There is no game over screen yet, so a print marks the moment. The fence number is tracked and ready for one.
  • Remove your Section 5 test enemies from the main scene. The WaveManager spawns enemies now, and a leftover test enemy would keep the group from ever emptying.

Testing the Wave System

  • Press F6. Nothing spawns yet, waves wait for you to press your button.
  • Press your start_wave key. Enemies walk the path one at a time, in entry order, spaced by your spawn interval.
  • Build wave_1 with two enemy types. The first entry's enemies all spawn before the second entry's begin.
  • Let your towers kill them all. The Output panel prints "Wave complete".
  • Make a second wave resource with different entries, add it to the waves array, and play both waves. The second wave starts only after the first completes.
  • Build a boss wave, a wave resource with one boss entry marked is_boss, and play it. The Output panel prints "Boss wave!" before the first enemy spawns.
  • Let an enemy reach the Base. It stops there and hits the fence every attack interval, so the fence number drops by damage on each hit.
  • The wave does not complete while an enemy camps the Base. Kill it with your towers and the wave completes.
  • Let the fence fall. The Output panel prints "Game Over".
  • There is no HUD yet, so prints tell you what happened.
💡 If waves will not start:
  • Nothing happens on the key press: the start_wave action is missing from the Input Map, or WaveManager is not in the main scene.
  • Nothing happens on the key press: a previous wave never completed, so wave_active is still true. Check that the enemies group is empty.
  • "No more waves" on the first press: the waves array is empty. Drag wave_1.tres into a slot.
  • "Wave is empty" on the first press: the entries array is empty, or an entry has a count of 0. Check wave_1.tres.
  • Wrong enemy spawns: an entry's enemy_scene slot is empty or points at the wrong scene. Check wave_1.tres.
  • Enemies spawn at the wrong place: the path export is empty. Drag your Path node into the slot.
  • Enemies wrap back to the start instead of reaching the Base: follow.loop = false is missing from spawn_enemy.
  • Enemies keep spawning past the queue: One Shot is off on the SpawnTimer, so it keeps firing after spawning is done.
  • Wave never completes: a Section 5 test enemy is still in the scene, keeping the enemies group from emptying.
  • Fence number never drops: the path-end change is missing from enemy.gd, or damage is 0.
  • "Boss wave!" never prints: is_boss is off on the entry, or the print is missing from the queue loop in start_wave. Check the entry and the loop.
  • Error about Global not declared: the autoload is not added. Check the Autoload tab in Project Settings, with the name Global.
