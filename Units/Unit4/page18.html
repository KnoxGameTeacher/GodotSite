Section 18: Save System with JSON

Save and load progress and settings using JSON and user:// paths

What is saving?

Saving means writing the game's important numbers to a file on the player's computer, so they are still there next time the game opens. Godot hands you a dictionary of values, and JSON turns that dictionary into text a file can hold. Loading reads the text back and turns it into a dictionary again.

So far, every number has existed only while the game runs. Close the game and the wave, the gold, and the settings are gone, because variables reset when the program stops. A save file is the first time your game's memory outlives a single run. JSON is just the format for that memory: text shaped like the dictionaries you already know, so it is easy to read and hard to break.

Numbers to Text

  • Saving means turning the game's numbers into text and writing that text to a file. JSON is the format, user:// is the folder.
  • Open scripts/main.gd. Saving will be in the same script as the menu, because one script owns the game around the game.
  • Add the save path and save_game to scripts/main.gd:

const SAVE_PATH = "user://save.json"

func save_game():
	var data = {
		"current_wave": Global.current_wave,
		"fence_durability": Global.fence_durability,
		"gold": Global.gold
	}
	var file = FileAccess.open(SAVE_PATH, FileAccess.WRITE)
	file.store_string(JSON.stringify(data))
	file.close()
	print("Game saved")
  • The path is in one constant, so save and load can never disagree about the filename.
  • user:// is Godot's folder for player files. It is outside your project, so a save survives closing the game and reopening it.
  • Add a Button named "SaveButton" to the pause panel, beside ResumeButton, and set its text to Save.
  • Connect the Save button's pressed signal, and add the handler to scripts/main.gd:

func _on_save_button_pressed():
	save_game()
  • Buttons will work while paused. The pause menu is Always, so its buttons hear clicks even when the game is frozen.
  • Press Esc and the menu appears. Press Save, the Output panel prints Game saved. Press Resume, the game continues.

Text Back to Numbers

  • Loading reverses saving. Read the text, parse it back into a dictionary, and put the numbers back in Global.
  • Add load_game to scripts/main.gd:

func load_game():
	if not FileAccess.file_exists(SAVE_PATH):
		print("No save file")
		return
	var file = FileAccess.open(SAVE_PATH, FileAccess.READ)
	var text = file.get_as_text()
	file.close()
	var data = JSON.parse_string(text)
	if data == null:
		print("Save file is broken")
		return
	Global.current_wave = data.get("current_wave", 0)
	Global.fence_durability = data.get("fence_durability", 20)
	Global.gold = data.get("gold", 100)
	print("Game loaded")
  • The file_exists check comes first because loading with no save would crash the game.
  • The null check comes second so that parse_string returns null when the text is not valid JSON. This way a damaged file prints a message instead of crashing.
  • .get with a default means an old save missing a key still loads. Each number falls back to its starting value.
  • After reopening the game, a load lands in the buy phase, since the wave state itself is not saved.
  • Add a Button named "LoadButton" to the pause panel, beside SaveButton, and set its text to Load.
  • Connect the Load button's pressed signal, and add the handler to scripts/main.gd:

func _on_load_button_pressed():
	load_game()
  • Save from the pause menu, spend some gold, load from the pause menu, and watch the gold label jump back to the saved amount.

Adding Settings

  • Section 17 built the settings dictionary and the controls. We won't declare them again, this step saves what is already there.
  • Settings are just more numbers, so they ride in the same file. Add the settings line to the data dictionary in save_game:

	var data = {
		"current_wave": Global.current_wave,
		"fence_durability": Global.fence_durability,
		"gold": Global.gold,
		"settings": settings
	}
  • In load_game, read settings back and apply them, right after the gold line:

	settings = data.get("settings", settings)
	apply_settings()
  • The .get default keeps your current settings when an old save has no settings key.
  • Apply settings as part of loading, so the volume and mute state are correct from the first moment.
  • Add apply_settings to scripts/main.gd:

func apply_settings():
	var volume = settings.get("master_volume", 1.0)
	volume_slider.value = volume
	mute_checkbox.button_pressed = settings.get("muted", false)
	AudioServer.set_bus_volume_db(0, linear_to_db(maxf(volume, 0.0001)))
	AudioServer.set_bus_mute(0, settings.get("muted", false))
  • .get with defaults means a damaged or partial settings block still loads. Volume falls back to full, mute falls back to off.
  • The slider and checkbox are set from the loaded values, so the menu should show the correct state instead of its defaults.

The Field Is Part of the Save

  • Numbers alone make a broken load. Save with 100 gold, spend it on towers, load, and the gold comes back while the towers stay. That is free money, forever. Loading must rebuild the field exactly as saved, so gold and towers always agree.
  • Track placed towers in scripts/placement.gd. Each entry holds the tower node and its index into tower_scenes:

var placed_towers = []
  • Record each placement at the end of try_place, after the zone is marked occupied:

	placed_towers.append({"node": tower, "index": selected_index})
  • Turn the list into saveable data. JSON holds only simple types, so a position becomes three numbers in an array:

func get_tower_data():
	var data = []
	for entry in placed_towers:
		var pos = entry["node"].global_position
		data.append({"index": entry["index"], "position": [pos.x, pos.y, pos.z]})
	return data
  • Rebuild the field on load. Clear the old towers, free every zone, then place the saved ones again. Add load_towers to scripts/placement.gd:

func load_towers(tower_data):
	for entry in placed_towers:
		entry["node"].queue_free()
	placed_towers.clear()
	for node in get_tree().get_nodes_in_group("placement_zones"):
		var zone = node as PlacementZone
		zone.occupied = false
	for entry in tower_data:
		var tower = tower_scenes[entry["index"]].instantiate()
		add_child(tower)
		var pos = Vector3(entry["position"][0], entry["position"][1], entry["position"][2])
		tower.global_position = pos
		for node in get_tree().get_nodes_in_group("placement_zones"):
			var zone = node as PlacementZone
			if zone.global_position.distance_to(pos) < 0.01:
				zone.occupied = true
		placed_towers.append({"node": tower, "index": entry["index"]})
  • The zone match checks closeness, not equality. Positions rarely survive a file round trip bit for bit, so a tiny distance might exist.
  • The cast to PlacementZone is the Section 7 trick again. The group hands back plain nodes, and occupied only exists on PlacementZone.
  • Wire the field into the save. Add the placement reference to scripts/main.gd, the towers line to save_game, and the load line to load_game, after the gold line and before the settings lines:

@onready var placement = $Placement

		"settings": settings,
		"towers": placement.get_tower_data()

	Global.gold = data.get("gold", 100)
	placement.load_towers(data.get("towers", []))
  • The empty default is important. Saves from before this step have no towers key, so they load with an empty field instead of crashing. This is something to remember when creating any save file.

Testing the Save File

  • Place towers, save from the pause menu, place more towers, load. Only the saved towers stand, and gold matches the save.
  • Close the game completely and reopen it. Load from the pause menu. Your saved towers return, and the HUD labels show your wave, fence, and gold.
  • Save from the pause menu, then load from it. Change gold first. Spend on a tower, save, spend more, load, and watch the gold label jump back to the saved amount.
  • Change the volume, save from the pause menu, close the game, reopen it, and load. The slider sits where you left it, and the bus matches.
  • Open the pause menu after loading. The slider and checkbox show the loaded values, not their defaults.
  • Delete user://save.json, then load from the pause menu. The Output panel prints No save file, and nothing breaks.
💡 If saving will not work:
  • Nothing saves: the save path is wrong, or save_game is never called. Check the SaveButton connection.
  • Save button does nothing: the pressed signal is not connected. Check the SaveButton connections.
  • Load button does nothing: the pressed signal is not connected. Check the LoadButton connections.
  • Load prints No save file: no save exists yet. Save first, then load.
  • Load prints Save file is broken: the JSON is damaged. Delete save.json and save again.
  • Loaded numbers are wrong: the save dictionary is missing a key, or load reads a different key than save wrote. Check the key names match on both sides.
  • Settings reset on load: the settings key is missing from the save dictionary, or apply_settings is never called in load_game. Check Step 3.
  • Menu shows defaults after load: apply_settings never ran, or it sets the bus but not the controls. Check that it sets volume_slider.value and mute_checkbox.button_pressed.
  • Towers missing after load: load_towers is never called, or the towers key is missing. Check load_game.
  • Towers doubled after load: placed_towers never cleared. Check load_towers clears first.
  • Zone stays blocked after load: the zone match failed. Check the distance check.
  • Old save loads an empty field: saves from before Step 4 have no towers key. The empty default handles it, but the field starts empty.
