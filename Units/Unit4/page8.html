Section 8: State Machine Fundamentals

Learn state machines and build Idle and Targeting states.

Section Progress: 0%
What is a state machine?

A state machine is a way to organize behavior. Your tower has one job at a time: sit still, track a target, attack, or wait out a cooldown. The machine is one variable that says which job is current, and a match that runs the right code for that job. Only one state is active at a time, so behaviors never fight each other.

You have done this before with if statements and true/false flags. A flag for tracking plus a flag for attacking plus a flag for cooling down works until two flags turn on at once and the tower tries to do two jobs. A state machine replaces the pile of flags with one variable. Instead of asking "is it tracking and is it attacking," the code asks "what state is it in," and the answer is always exactly one thing. This concept becomes more important the more behaviors you have.

1

One State Machine

  • A state machine is one variable that says what the tower is doing right now, plus one match that runs the right behavior for that state.
  • Open your tower scene from Section 3 and attach a script to the root. Save it as scripts/tower.gd.
  • Start the script with the machine itself:
extends Node3D

enum State { IDLE, TARGETING }

@export var attack_range = 10.0
@export var faces_target = true

var state = State.IDLE
var target: Node3D = null

func _process(delta):
	match state:
		State.IDLE:
			pass
		State.TARGETING:
			pass
  • The enum lists the states. The state variable holds the current one, while the match tells the behavior.
  • Mine is 10 for attack_range, but yours can be anything. Your GDD decides how far your towers reach. Set it in the Inspector.
  • faces_target is on by default. A tower that should stay still turns it off in the Inspector. This may not be important for your game, mine needed this
  • Section 9 adds Attacking and Cooldown to this same match. You will not rewrite the machine, you will add two states to it. This is why we're using this system.

Nearest Enemy in Range

  • Towers find enemies through the enemies group from Section 4. Every enemy scene carries that tag.
  • Replace the pass under State.IDLE with a search:
		State.IDLE:
			target = find_target()
			if target != null:
				state = State.TARGETING
  • Idle has one job, to look for a target. The moment one exists, the machine switches states.
  • Add find_target() to scripts/tower.gd:
func find_target():
	var nearest: Node3D = null
	var nearest_distance = attack_range
	for enemy in get_tree().get_nodes_in_group("enemies"):
		var distance = global_position.distance_to(enemy.global_position)
		if distance < nearest_distance:
			nearest = enemy
			nearest_distance = distance
	return nearest
  • The loop checks every enemy in the group and keeps the nearest one inside attack_range.
  • Starting nearest_distance at attack_range means an enemy outside the range can never steal aggro. No separate range check is needed.
Figure 8.2: Finding the nearest target
3

Track Until Out of Range

  • Replace the pass under State.TARGETING:
		State.TARGETING:
			if not is_instance_valid(target) or global_position.distance_to(target.global_position) > attack_range:
				target = null
				state = State.IDLE
			else:
				if faces_target:
					face_target()
  • Targeting has two exit conditions, either the target despawned, or it walked out of range. Either way the tower drops it and goes back to Idle.
  • A tower with faces_target off still acquires and keeps its target, it just does not turn. Attacking in Section 9 works the same either way.
  • is_instance_valid is very important. A freed enemy is not null, so a null check alone would keep a dead target, but this check catches it.
  • Add face_target to scripts/tower.gd:
func face_target():
	var direction = target.global_position - global_position
	direction.y = 0
	if direction.length() > 0.01:
		look_at(global_position + direction, Vector3.UP)
  • Flattening direction to the ground with direction.y = 0 keeps the tower from tilting up or down toward the enemy.
  • The length check stops look_at from breaking if the enemy stands exactly on the tower.
Figure 8.3: Tower facing its target
4

Ghosts Shouldn't Target

  • Your preview ghost from Section 6 is a full tower scene, so it would run this script too. A ghost that tracks enemies is a bug.
  • Open scripts/placement.gd and add one line to _ready, right after add_child(preview):
	preview.set_process(false)
  • Turning off processing stops the ghost's _process without touching the real towers. The ghost still shows, moves, and hides exactly as before.
  • The line must come after add_child(preview). Before add_child, the preview is not in the tree yet, so set_process(false) has nothing to switch off.
Figure 8.4: Disabling processing on the preview

A Circle Around the Ghost

  • The tower knows its range, but the player cannot see it. While placing, we want to show a circle on the ground around the ghost as wide as attack_range.
  • Add a MeshInstance3D child to the tower scene root and name it "RangeRing". Give it a CylinderMesh with Top Radius 1, Bottom Radius 1, and Height 0.1. Turn Visible off in the Inspector, and set its position y to 0.1 so it floats above the ground instead of z-fighting it.
  • As written, the ring stays hidden on placed towers. Placement shows it on the preview only, so active towers won't have circles.
  • The ghosting from Section 6 makes the ring faint automatically, so no material work is needed. make_ghost covers every mesh in the preview, ring included.
  • Placement needs the tower's type to read attack_range. Add the class name as the first line of scripts/tower.gd, above extends:

class_name Tower
  • This is the same class name trick as PlacementZone in Section 7.
  • Change the preview declaration at the top of scripts/placement.gd to Tower, and the build line to cast the instance:

var preview: Tower

	preview = tower_scene.instantiate() as Tower
  • instantiate returns a plain Node, so the cast tells Godot it is a Tower. Without it, assigning to a Tower variable errors.
  • Add the ring lines to _ready in scripts/placement.gd, right after the set_process line from Step 4:

	var ring = preview.get_node("RangeRing") as MeshInstance3D
	ring.visible = true
	ring.scale = Vector3(preview.attack_range, 1, preview.attack_range)
  • The cylinder's radius is 1, so scaling x and z by attack_range makes a circle exactly as wide as the tower can shoot. y stays 1, so the height does not change.
  • The ring is a child of the preview, so it hides when the preview hides and uses the ghost's position on its own. No hover code changes are needed.
  • Hover a zone. A faint circle appears around the ghost. Set attack_range to 5 in the Inspector and hover again. The circle shrinks.
Figure 8.5: Range circle around the placement ghost
6

Testing Idle and Targeting

  • Place a tower near the path, the way Section 7 taught you.
  • Press F6. An enemy walks the path from Section 5.
  • While the enemy is far away, the tower sits still. That is Idle.
  • When the enemy comes in range, the tower turns to face it. That is Targeting.
  • Turn faces_target off on a tower and test again. It holds still instead of turning. The state is the same. Only the turning is skipped.
  • When the enemy walks out of range or despawns at the Base, the tower stops turning. That is Idle again.
  • Hover a zone. A faint circle appears around the ghost, reaching as far as the tower can shoot.
  • Not sure the state is changing? Add a temporary print(state) at the top of _process and watch the Output panel. It prints 0 for Idle and 1 for Targeting.
💡 Debugging:
  • Tower never targets: the enemy is not in the enemies group. Check the Groups tab on the enemy scene.
  • Tower never targets: attack_range is too small or was never set in the Inspector. Check the tower scene.
  • Tower never targets: the script is attached to the wrong node. It belongs on the tower scene root.
  • Tower faces away from the enemy: rotate the Model child 180 degrees around Y, the same fix as Section 5.
  • Tower stays still instead of turning: faces_target is off in the Inspector.
  • Tower keeps facing a despawned enemy or errors about a freed instance: the is_instance_valid check is missing from Targeting.
  • Ghost preview turns toward enemies: preview.set_process(false) is missing from placement.gd.
  • Projectiles fire from nowhere, or the ghost fires while invisible: set_process(false) is before add_child(preview) in placement.gd, so it never took effect. Move it to after add_child(preview).
  • Ring never shows: the ring lines are missing from _ready, or the node is not named RangeRing. Check both.
  • Ring shows on placed towers: RangeRing Visible is on in the tower scene. Turn it off; placement shows it on the preview only.
  • Ring wrong size: the scale uses the wrong value. Check preview.attack_range.
  • Ring under the ground: position y is 0. Lift it to 0.1.
  • Error about assigning Node to Tower: the as Tower cast is missing from the instantiate line. Check _ready.
  • Tower targets enemies across the whole map: that is range working as taught. There is no line of sight check in this section.
