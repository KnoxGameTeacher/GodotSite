Section 15: Pause Menu, HUD, and Wave Summary

Build a pause menu, a HUD, and a wave summary panel

Section Progress: 0%
1

Setting Up

  • Menus are not 3D elements, they are on a CanvasLayer, a 2D layer drawn above the game that never moves with the camera.
  • Attach a script to your main scene root and save it as scripts/main.gd. This is where we'll put menu code.
  • Add a CanvasLayer to your main scene and name it "PauseMenu".
  • Add a Panel child to PauseMenu.
  • Add a Button child to the panel, name it "ResumeButton", and set its text to Resume.
  • Turn off Visible on PauseMenu in the Inspector, so the menu starts hidden.
  • Set PauseMenu's Process Mode to Always in the Inspector. This is the step everyone forgets, and the menu will not work without it.
  • Add a pause_menu reference to scripts/main.gd:
@onready var pause_menu = $PauseMenu
  • A CanvasLayer draws its children as flat UI, no matter where the 3D camera goes.
  • Visible off means the menu is there, but invisible to the player until we change that property.

Coding the Pause Functionality

  • Add a new input action for pausing. Open Project Settings, go to Input Map, add an action called "pause", and give it a key. Mine is Esc.
  • Add toggle_pause to scripts/main.gd:

func toggle_pause():
	get_tree().paused = not get_tree().paused
	pause_menu.visible = get_tree().paused
  • Connect the Resume button's pressed signal to a handler that calls toggle_pause:

func _on_resume_button_pressed():
	toggle_pause()
  • Add input handling to scripts/main.gd:

func _unhandled_input(event):
	if event.is_action_pressed("pause"):
		toggle_pause()
  • Pausing flips the boolean value that controls the menu's visibility.
  • The main script pauses with the game, so it cannot hear any action presses not on the menu.
💡 If the pause menu will not respond: Check the PauseMenu's Process Mode first. When the game is paused, every node with the default Process Mode pauses too, including your menu's buttons. Setting it to Always keeps the menu alive while the game is frozen.

Player Interface

  • Add a second CanvasLayer to your main scene and name it "HUD".
  • Set its Layer to 0, so the pause menu (Layer 1 by default) always draws above it.
  • Add three Labels: GoldLabel, WaveLabel, and FenceLabel. Place them where players can read them at a glance.
  • Add a Button named "StartWaveButton" and set its text to Start Wave.
  • Add one tower Button per tower scene. Mine has four, so I have four buttons. Set each button's text to that tower's name and cost, so players know what they are buying.
  • Attach a script to HUD and save it as scripts/hud.gd.
  • Add label, button, and system references to scripts/hud.gd:

@onready var gold_label = $GoldLabel
@onready var wave_label = $WaveLabel
@onready var fence_label = $FenceLabel
@onready var start_wave_button = $StartWaveButton
@onready var wave_manager = $"../WaveManager"
@onready var placement = $"../Placement"
  • HUD sits beside WaveManager and Placement in the main scene, so $"../" tells the HUD it is in a higher level in the scene tree.
  • Update the labels and the button state every frame in scripts/hud.gd:

func _process(delta):
	gold_label.text = "Gold: " + str(Global.gold)
	wave_label.text = "Wave: " + str(Global.current_wave + 1)
	fence_label.text = "Fence: " + str(Global.fence_durability)
	start_wave_button.disabled = wave_manager.wave_active
  • current_wave counts finished waves, so the next wave is current_wave + 1.
  • While a wave runs, the Start Wave button disables itself, so players cannot start two waves at once.
  • Connect the button pressed signals, and add the handlers to scripts/hud.gd:

func _on_start_wave_button_pressed():
	wave_manager.start_wave()

func _on_tower_1_button_pressed():
	placement.select_tower(0)

func _on_tower_2_button_pressed():
	placement.select_tower(1)

func _on_tower_3_button_pressed():
	placement.select_tower(2)
  • The button and the Space key call the same function.
  • Tower buttons call select_tower, the same function the number keys call.
  • HUD and PauseMenu are separate CanvasLayers because one is always visible and the other hides.
  • As written, you will need to manually update the button texts when tower costs change.

Info Pause Between Waves

  • Between waves is the buy phase, and traditionally these games would have a summary screen between waves. Add a Panel child to HUD and name it "SummaryPanel".
  • Add a Label child to SummaryPanel and name it "SummaryLabel".
  • Add a Button child to SummaryPanel, name it "BuyPhaseButton", and set its text to Start Buy Phase.
  • Turn off Visible on SummaryPanel in the Inspector, so it starts hidden.
  • Set SummaryPanel's Process Mode to Always in the Inspector, the same step as PauseMenu. The panel pauses the game when it shows, so its button must stay alive while everything else freezes.
  • Add class_name HUD as the first line of scripts/hud.gd, above extends, the same trick as Tower in Section 8. WaveManager needs the type to call the summary:

class_name HUD  
extends CanvasLayer
  • To give the player some information on their wave results, we need to track the wave's economics. Add an earnings total to scripts/global.gd, beside gold:

var fence_durability = 20
var gold = 100
var gold_earned = 0
  • Earnings will have to be in Global, since the kill pay in enemy.gd and the bonus in wave_manager.gd both need to reach them.
  • Add a starting-gold snapshot to scripts/wave_manager.gd, next to the other state:

var current_cycle = 0
var current_wave_def: WaveDef
var gold_at_wave_start = 0
  • Add two lines to start_wave in scripts/wave_manager.gd, right after the empty guard and before the queue builds:

func start_wave():
	if waves.is_empty():
		print("No waves")
		return
	gold_at_wave_start = Global.gold  
	Global.gold_earned = 0  
	var def_index = Global.current_wave % waves.size()
  • Starting gold is a snapshot, so mid-wave spending never corrupts it, and earnings count gross, so spending never shrinks them.
  • Earnings reset every wave, so no save entry is needed.
  • Count earnings in the kill branch of take_damage in scripts/enemy.gd, beside the gold pay:

	health -= effective
	if health <= 0:
		Global.gold += gold_reward
		Global.gold_earned += gold_reward 
		get_parent().queue_free()
  • Earnings count through take_damage, so direct hits, splash, and burn all count the same way.
  • Add panel references and the summary function to scripts/hud.gd:

@onready var wave_manager = $"../WaveManager"
@onready var placement = $"../Placement"
@onready var summary_panel = $SummaryPanel  
@onready var summary_label = $SummaryPanel/SummaryLabel 

func show_wave_summary():
	var text = "Wave " + str(Global.current_wave) + " complete!"
	text += "\nStarting gold: " + str(wave_manager.gold_at_wave_start)
	text += "\nGold earned: " + str(Global.gold_earned)
	summary_label.text = text
	summary_panel.visible = true
	get_tree().paused = true
  • The popup reads the snapshot and the earnings total, so it shows what the wave started with and what it paid, not just the current total.
  • Current gold stays on the HUD label, and fence stays on its label, so the popup does not repeat them.
  • wave_manager already has a reference in hud.gd from Step 3, so the snapshot is one member away.
  • The \n inside the text breaks the label into three lines.
  • Connect the Buy Phase button's pressed signal, and add the handler to scripts/hud.gd:

	summary_panel.visible = true
	get_tree().paused = true

func _on_buy_phase_button_pressed():  
	summary_panel.visible = false
	get_tree().paused = false
  • Pressing the button unpauses into the buy phase, where wave_active is false and towers can be placed.
  • Call the summary from the completion check in scripts/wave_manager.gd. Add a hud reference beside the spawn_timer reference:

@onready var spawn_timer = $SpawnTimer
@onready var hud = get_parent().get_node("HUD") as HUD  

var wave_active = false
  • Add the call to the completion check, so the full check now reads:

func _process(delta):
	if wave_active and spawning_done and get_tree().get_nodes_in_group("enemies").is_empty():
		wave_active = false
		Global.current_wave += 1
		Global.gold += 25
		Global.gold_earned += 25  
		print("Wave complete")
		hud.show_wave_summary()
  • The bonus pays into both totals, so the popup's earned line includes the 25.
  • The gold line from Section 14 stays, so the summary joins it instead of replacing it.
  • current_wave already counted up by the time the summary shows, so the wave just finished is current_wave, not current_wave + 1.

Testing UI

  • Press Esc. The game freezes and the menu appears. Press Resume. The game continues.
  • Try placing a tower while paused. Nothing happens. Paused nodes cannot hear input, which is why the menu needs its process set to Always.
  • Kill an enemy. The gold label jumps. Spend on a tower. It drops. The labels track Global with no prints needed.
  • Press Start Wave. A wave starts. Press a tower button. The ghost switches to that tower.
  • Start a wave, then look at Start Wave. It is greyed out until the wave ends.
  • Press Esc. The pause menu draws above the HUD.
  • Complete a wave. The popup appears with the wave number, starting gold, and gold earned, and the game freezes behind it. Press Start Buy Phase. The panel hides and the buy phase begins, with towers placeable and Start Wave ready for the next wave.
  • Place a tower mid-wave, then finish the wave. Starting gold still shows the pre-wave total, and earned still counts the full kills plus the bonus.
💡 If the menu will not work:
  • Menu never appears: the pause action is missing, or toggle_pause is never called. Check Input Map and _unhandled_input.
  • Menu appears but buttons do nothing: Process Mode is not Always. Check PauseMenu in the Inspector.
  • Menu shows at game start: Visible is still on for PauseMenu. Turn it off in the Inspector.
  • Resume does nothing: the pressed signal is not connected. Check the ResumeButton connections.
  • Esc pauses but never resumes: that is the design. The main script pauses with the game, so Resume is the way back.
  • Gold label never changes: hud.gd is not updating it, or the label path is wrong. Check _process and the label names.
  • Start Wave button does nothing: the pressed signal is not connected, or the WaveManager path is wrong. Check the connections and $"../WaveManager".
  • Tower buttons do nothing: the pressed signal is not connected. Check the connections, and that select_tower is called.
  • HUD draws over the pause menu: the HUD's Layer is not below the pause menu's. Set HUD Layer to 0.
  • Wave label shows the wrong number: current_wave counts finished waves, so the next wave is current_wave + 1. Check the + 1.
  • Summary never shows: show_wave_summary is never called from the completion check. Check wave_manager _process.
  • Start Buy Phase does nothing: SummaryPanel Process Mode is not Always. Check the panel in the Inspector.
  • Game stays paused after Start Buy Phase: paused = false is missing from the handler. Check _on_buy_phase_button_pressed.
  • Earned total looks wrong: gold_earned never resets in start_wave, or the take_damage line is missing. Check both.
  • Starting gold looks wrong: gold_at_wave_start is never set in start_wave. Check the snapshot line.
