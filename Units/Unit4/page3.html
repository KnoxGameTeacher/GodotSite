What Is Asset Forge?

  • Asset Forge is a block-building tool by Kenney for creating 3D models
  • You snap together pre-made blocks, no modeling experience needed
  • The downside to this program compared to the other two options presented is that it costs money
  • Anything you create is yours to use, and the included blocks are public domain
Getting Oriented
  • Open Asset Forge and start a new project
  • Browse the block library. Blocks are grouped by category.
  • Drag blocks into the build area and stack them however you like

What Is Blockbench?

  • Blockbench is a free, open source 3D model editor at blockbench.net
  • It runs in your browser, so there is nothing to install
  • It is built for boxy, low-poly models, which fits this game perfectly
  • It exports glTF, which Godot reads directly
Starting Your First Model
  • Open Blockbench and choose New Model, then pick Generic Model
  • You get an empty workspace with a grid. Cuboids are your building blocks.
  • You only need a handful of tools for this unit: add, move, resize, rotate, and paint
💡 Note: Blockbench gives you more control than snap-together tools, so there are a few more buttons to learn. Stick to the five tools above and you will be fine.
Figure 3.1: The Blockbench workspace with a new generic model
1

What Is Blender?

  • Blender is a free, open source 3D creation suite at blender.org
  • It is the most capable tool on this page, and the steepest learning curve
  • It exports glTF, which Godot reads directly
Starting Your First Model
  • Open Blender and start a new General project
  • Delete the default cube. Select it and press X.
  • Press Shift+A, then Mesh, then Cube to add your first block
  • You only need a handful of operations for this unit: add (Shift+A), move (G), scale (S), and rotate (R)
💡 Note: Blender can do almost anything, which means a lot of buttons you will never touch here. Stick to the operations above and treat the rest as scenery.
Figure 3.1: The Blender workspace with a new project

Design Before You Build

  • Open your GDD and look at your tower roster
  • Make the silhouettes distinct, players should tell towers apart at a glance
  • Example: a tall, thin tower for long-range attacks vs. a short, wide tower for close-range defense
💡 GDD Check: Build the roster you designed. If your GDD has three towers, build three. If it has five, build five. The number and roles come from your design decisions.
Figure 3.2: Distinct silhouettes make towers readable in-game
3

Assemble in Layers

  • Start with your simplest tower
  • Build from the ground up in three layers: base, body, top
  • Give the top layer something distinctive, that's what players see from the perspective over the field
  • Keep it chunky: tiny details disappear at game distance
Saving Your Work
  • Save the Asset Forge project file for each tower
  • You'll need it later if a tower needs changes, you can then easily edit and re-export it

Color as Communication

  • Use color to tell players what a tower does
  • Pick one color scheme for your whole game and stick to it across every tower
  • Repeat the same color logic everywhere, for example, if your sniper tower is red, all sniper towers should be red
💡 GDD Check: What mood and setting did you choose? Your colors should match your game's visual direction but still stand out enough in the environment that the player can easily manage the field.

Exporting Your Towers

  • Export each tower as its own file
  • Choose the glTF format
  • Name your files with a consistent scheme, like tower_cannon.glb
  • Repeat for every tower in your roster
Figure 3.5: Exporting a tower as a .glb file

Exporting Your Towers

  • Export each tower as its own file
  • Go to File, then Export, then Export glTF Model
  • This produces a single .glb file per tower
  • Name your files with a consistent scheme, like tower_cannon.glb
  • Repeat for every tower in your roster
Figure 3.5: Exporting a tower as a .glb file
5

Exporting Your Towers

  • Export each tower as its own file
  • Go to File, then Export, then glTF 2.0
  • Choose the .glb format for a single tidy file
  • Name your files with a consistent scheme, like tower_cannon.glb
  • Repeat for every tower in your roster
Figure 3.5: Exporting a tower as a .glb file
6

Bringing Towers into Your Project

  • Drag your .glb files into assets/towers/ in the FileSystem dock
  • Double-click one to preview it in the editor
  • Drag one into a test scene to check that it looks right at game scale
💡 Note: If a tower looks wrong, go back to your project file in your modeling tool, make the change there, and re-export.
