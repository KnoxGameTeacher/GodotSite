Section 9: Attacking & Cooldown States

Complete the state machine with Attacking and Cooldown.

Section Progress: 0%
1

Two States Join the Machine

  • Open scripts/tower.gd from Section 8
  • Add two states to the enum:
enum State { IDLE, TARGETING, ATTACKING, COOLDOWN }
  • Add two exports for the attack numbers:

@export var attack_damage = 10
@export var cooldown_time = 1.0
  • Mine is 10 damage and 1 second of cooldown, but yours can be anything. Your GDD decides how hard your towers hit and how long they wait between attacks.
  • Nothing else in the machine changes, this is the power of state machines. No rework is needed.
Figure 9.1: New states in the tower enum
2

Adding a Timer Node

  • Add a Timer child to your tower scene root and name it "CooldownTimer"
  • In the Inspector, turn on One Shot. Without it, the timer repeats instead of stopping.
  • Connect the Timer timeout signal to the tower script. Godot creates _on_cooldown_timer_timeout for you. Step 5 fills it in.
  • Add a reference to the timer and set its wait time from the export. Add this to scripts/tower.gd:

@onready var cooldown_timer = $CooldownTimer

func _ready():
	cooldown_timer.wait_time = cooldown_time
  • Setting wait_time from cooldown_time means the number lives in one place. Change the export value and the timer changes.
Figure 9.2: Cooldown timer in the tower scene
3

Health and Taking Damage

  • Open scripts/enemy.gd
  • Give the script a class name, the same trick as PlacementZone in Section 7. Add it under the extends line:

extends CharacterBody3D
class_name Enemy
  • Add a health variable and set it from max_health in _ready. max_health comes from Section 4. If yours is missing it, add the export too.

var health = 0

func _ready():
	health = max_health
  • Add take_damage. When health runs out, the enemy dies:

func take_damage(amount):
	health -= amount
	if health <= 0:
		get_parent().queue_free()
  • Freeing the parent PathFollow takes the enemy with it, the same idea as the path-end despawn in Section 5.
  • The check is <=, not ==, because a hit could overshoot the last point of health.
  • Finally, in scripts/tower.gd, type the target as Enemy instead of Node3D, and do the same for nearest in find_target. Node3D does not know about take_damage, but Enemy does.
var target: Enemy = null
Figure 9.3: Enemy health and take_damage
4

From Targeting to Attacking

  • TARGETING already faces the target. Change its ending so it hands off to the new state:
		
State.TARGETING:
    if not is_instance_valid(target) or global_position.distance_to(target.global_position) > attack_range:
        target = null
        state = State.IDLE
    else:
        if faces_target:
            face_target()
        state = State.ATTACKING
  • Add the ATTACKING branch to the match:
		
State.ATTACKING:
    if not is_instance_valid(target):
        target = null
        state = State.IDLE
    else:
        target.take_damage(attack_damage)
        cooldown_timer.start()
        state = State.COOLDOWN
  • The validity check is important. Two towers can target the same enemy, and the first one to land a killing hit frees it. Without this check, the second tower attacks a freed instance and errors.
  • Attacking deals damage directly for now. Section 10 gives this attack a projectile to travel in, and take_damage stays exactly as it is.
💡 Note: Attacking does its job in one frame. Deal the damage, start the timer, move on. The waiting is in Cooldown, not here.
Figure 9.4: Attacking branch in the state machine
5

A State That Waits

  • Add the COOLDOWN branch to the match. It does nothing per frame except wait for the timer to finish:
		
State.COOLDOWN:
	pass
  • Fill in the timeout handler from step 2:

func _on_cooldown_timer_timeout():
	if is_instance_valid(target) and global_position.distance_to(target.global_position) <= attack_range:
		state = State.TARGETING
	else:
		target = null
		state = State.IDLE
  • When the timer finishes, the tower checks whether the fight is still on. Target alive and in range means back to Targeting. Anything else means back to Idle.
  • A state does not need per-frame behavior. Some states just wait for a signal, and that is a normal way to build a state machine.

Testing Attacks and Cooldowns

  • Place a tower near the path, the way Section 7 taught you.
  • Press F6. An enemy walks the path from Section 5.
  • When the enemy comes in range, the tower attacks. With a temporary print in take_damage, you can watch the health drop hit by hit.
  • After enough hits, the enemy disappears mid-path instead of reaching the Base. That is a kill.
  • Attacks have gaps between them. Count the seconds. The gap should match your cooldown_time.
  • Place a second tower near the same stretch of path. Both towers attack the same enemy with no freed instance error.
  • When the enemy dies or walks out of range, the tower goes back to Idle.
💡 If the tower will not attack:
  • Tower never attacks: the timeout signal is not connected, or TARGETING never hands off. Check the state = State.ATTACKING line.
  • Tower attacks once then stops: the timer never started. Check cooldown_timer.start() in ATTACKING, and check the timeout signal connection.
  • Tower attacks with no gap: cooldown_time is 0, or ATTACKING skips Cooldown. Check that ATTACKING sets state = State.COOLDOWN.
  • Timer keeps firing with nothing happening: One Shot is off, so the timer repeats instead of stopping.
  • Enemy never dies: attack_damage is too low for max_health, or take_damage is not reducing health. Check the health -= amount line and your GDD numbers.
  • Freed instance error with two towers: the validity check is missing from ATTACKING.
  • Error or warning about take_damage: the target is still typed as Node3D, or enemy.gd is missing class_name Enemy.
