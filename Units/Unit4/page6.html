Section 6: Placement Zones & Preview

Create valid tower placement spots with a hover preview.

Section Progress: 0%
1

The Zone Scene

  • Create a new scene with an Area3D root
  • Rename it to "PlacementZone"
  • Add a CollisionShape3D child and give it a shape that covers the spot a tower will sit on
  • Add a MeshInstance3D child and name it "Marker". Give it a flat shape so players can see where zones are. The marker is a placeholder look. You can dress it up later.
  • Save the scene as scenes/placement_zone.tscn
  • Attach a script and save it as scripts/placement_zone.gd
extends Area3D

signal zone_hovered(zone)
signal zone_unhovered(zone)

func _ready():
	add_to_group("placement_zones")

func _on_mouse_entered():
	zone_hovered.emit(self)

func _on_mouse_exited():
	zone_unhovered.emit(self)
  • Connect the Area3D mouse_entered signal to _on_mouse_entered and the mouse_exited signal to _on_mouse_exited
  • The zone announces itself with signals instead of making other code hunt for zones
  • Every zone adds itself to the placement_zones group, so a zone you add later works with no extra setup
💡 GDD Check: Check your GDD. How many placement zones does your map need, and where do they sit relative to the path?

Zones on the Map

  • Open environment.tscn
  • Instance placement_zone.tscn beside the path. The number and layout come from your GDD.
  • Each zone is a separate instance. There is no extra setup per zone, because the script registers the group itself.
  • Press F6 and check the markers show up where you expect them.
💡 Note: Zones beside the path keep towers in range of the action. This might change if you have a very long range tower.

One Place for Placement Code

  • Add a Node child to your main scene and name it "Placement"
  • Attach a script and save it as scripts/placement.gd
  • Start the script with an export for the tower scene:
extends Node

@export var tower_scene: PackedScene
  • Drag your tower scene from Section 3 into the tower_scene slot in the Inspector
  • An export means swapping the tower later is one drag, not a code edit
  • All placement code lives in this one node. Section 7 adds clicking to this same script.

A See-Through Tower

  • Add this to scripts/placement.gd. It creates the preview when the game starts:
var preview: Node3D
var hovered_zone: Area3D

func _ready():
	preview = tower_scene.instantiate()
	make_ghost(preview)
	add_child(preview)
	preview.visible = false
	call_deferred("_connect_zones")

func _connect_zones():
	for zone in get_tree().get_nodes_in_group("placement_zones"):
		zone.zone_hovered.connect(_on_zone_hovered)
		zone.zone_unhovered.connect(_on_zone_unhovered)
  • call_deferred waits until every zone has registered itself, so the connections work no matter what order the nodes sit in
  • Next, the function that turns a tower see-through:
func make_ghost(node):
	if node is MeshInstance3D:
		var ghost_material = StandardMaterial3D.new()
		ghost_material.transparency = BaseMaterial3D.TRANSPARENCY_ALPHA
		ghost_material.albedo_color.a = 0.5
		node.material_override = ghost_material
	for child in node.get_children():
		make_ghost(child)
  • material_override changes only how the preview looks. Your tower model keeps its own materials.
  • The function walks the whole tower, so it works for any tower scene. A second tower type later needs no new code.
  • Finally, the handlers that show and hide the preview:
func _on_zone_hovered(zone):
	hovered_zone = zone
	preview.global_position = zone.global_position
	preview.visible = true

func _on_zone_unhovered(_zone):
	preview.visible = false
	hovered_zone = null
  • The preview sits at the hovered zone position. It does not follow the mouse, because only zones are valid spots. That is the whole point of zones.
  • hovered_zone is stored now because Section 7 will use it when the player clicks.

Testing the Preview

  • Press F6
  • Hover a zone. The ghost tower appears on that zone.
  • Move to another zone. The ghost jumps to it.
  • Move off all zones. The ghost disappears.
  • Clicking does nothing yet. That is Section 7.
💡 If the ghost will not show:
  • Nothing happens on hover: your scene needs a Camera3D. Mouse signals come from the camera, so no camera means no hover.
  • Ghost never appears and there is no error: check that the zone CollisionShape3D covers the marker. A shape that is too small or sitting elsewhere never gets hovered.
  • Error about instantiate: the tower_scene export slot is empty. Drag your tower scene into it.
  • Ghost appears but floats or sinks: your tower model origin is not at its base. Fix the origin in your tower scene.
  • Ghost stays visible after leaving a zone: the mouse_exited signal is not connected. Check the signal connections on the zone.
  • Clicking does nothing: correct for now. Placing is Section 7.
